Threat Scenario

Remote Code Execution on Telematics Unit via Cellular Air Interface

Target: Telematics Unit • Asset: Braking Signal • Status: APPROVED
Critical (20/25)

Vulnerabilities in the cellular modem firmware or MQTT telematics stack allow a remote adversary to achieve root shell execution on the TCU without physical vehicle access.

Attack Vector: Over-the-Air Cellular Baseband Buffer Overflow / Protocol Exploit
ISO 21434: Feasibility: Medium | SFOP: S:Severe, F:Major, O:Major, P:Severe | Risk Value: 3/5
Mitigations & Countermeasures:
  • [Preventive] Hardware Security Module (HSM) & Secure Boot (Effort: High, Status: proposed)
    Enforce cryptographic secure boot with hardware root-of-trust in HSM and isolate telematics runtime using ARM TrustZone or seL4 microkernel.
Attack Path & Feasibility

Lateral Pivot from Infotainment/TCU to Safety CAN Bus via Central Gateway

Target: System Wide • Asset: Braking Signal • Status: DRAFT
Medium (15/25)

Insufficient domain segregation or routing filter misconfigurations in the Central Gateway ECU permit arbitrary CAN frame injection onto the safety-critical chassis bus.

Attack Vector: CAN ID Spoofing across Central Gateway boundary
ISO 21434: Feasibility: Medium | SFOP: S:Severe, F:Major, O:Major, P:Low | Risk Value: 3/5
Mitigations & Countermeasures:
  • [Preventive] AUTOSAR Secure Onboard Communication (SecOC) & CAN IDS (Effort: High, Status: proposed)
    Implement SecOC with freshness values and MAC verification for all safety-relevant CAN-FD messages, coupled with CAN-bus Intrusion Detection Systems (IDS).
Damage Scenario (SFOP)

Malicious Firmware Flashing via Diagnostic OBD-II Interface

Target: System Wide • Asset: Architecture Asset • Status: DRAFT
Critical (20/25)

An attacker connected to the physical OBD-II diagnostic port bypasses SecurityAccess (UDS Service 0x27) to flash unauthorized modified calibration files or malicious firmware into vehicle ECUs.

Attack Vector: Physical OBD-II Port / UDS Diagnostic Protocol Exploit
ISO 21434: Feasibility: High | SFOP: S:Major, F:Major, O:Severe, P:Negligible | Risk Value: 5/5
Mitigations & Countermeasures:
  • [Preventive] Asymmetric Diagnostic Authentication & OBD-II Firewall (Effort: Medium, Status: proposed)
    Enforce ISO 13400-2 DoIP with TLS and asymmetric certificate-based authentication for diagnostic services (zero static seed-key algorithms).
Damage Scenario (SFOP)

Eavesdropping and Relay Attack on Passive Keyless Entry (PKE) BLE Interface

Target: System Wide • Asset: Architecture Asset • Status: DRAFT
Critical (20/25)

Adversaries employ wireless signal relay transceivers or Bluetooth Low Energy (BLE) spoofing to trick the vehicle into unlocking and enabling vehicle ignition without owner proximity.

Attack Vector: Sub-GHz / BLE Radio Frequency Relay Attack
ISO 21434: Feasibility: High | SFOP: S:Low, F:Severe, O:Major, P:Severe | Risk Value: 5/5
Mitigations & Countermeasures:
  • [Preventive] Ultra-Wideband (UWB) Time-of-Flight (ToF) Distance Bounding (Effort: High, Status: proposed)
    Replace or augment BLE with Ultra-Wideband (UWB) physical layer distance bounding to verify true physical proximity via speed-of-light measurements.
